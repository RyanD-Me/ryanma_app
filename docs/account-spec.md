# アカウント・段位戦・フレンド機能 仕様(2026-09-26 決定)

ユーザーと相談して決めた仕様。実装はこの文書に合わせる(変更したらこの文書も直す)。

## 0. 全体の構成

- 認証・データは **Firebase**(無料の Spark プラン)を使う。
  - メール送信: Firebase Authentication の「メールアドレス確認メール」(無料で 1日1,000通)をログイン用のメールとして使う。
    (「ログイン用リンク」メールは Spark プランでは 1日5通しか送れないため使わない)
  - データ: Firestore(無料で 容量1GB・読み込み 5万回/日・書き込み 2万回/日)。
- アカウント・段位・戦績・フレンドのデータは **ゲームサーバー(Render)だけが読み書きする**(ページから Firestore に直接触れない)。
  サーバー用の鍵は Render の環境変数に置き、リポジトリには入れない。
- ログインなしで遊ぶ形(ゲスト)は残す。

## 1. 登録・ログイン

### 認証の流れ(登録・再ログイン・別の端末・メールアドレス変更で共通)
1. ゲームでユーザー名(初回登録はメールアドレスも)を入力 → サーバーが「ログイン受付」を作り、Firebase に確認メールの送信を頼む。
2. メールのリンク → こちらで用意する確認ページ(GitHub Pages)が開く。確認ページはリンクの確認情報(oobCode)をサーバーへ送る。
3. サーバーが Firebase に問い合わせて、そのメールアドレスの持ち主が押したリンクか確かめ、**6桁の認証コード**を作って確認ページに表示する。
4. ゲームに認証コードを入力 → 受付と一致すれば登録/ログイン完了。

- 認証コード: 受付に結び付けた6桁。有効期限10分・1回限り・入力は5回まで。サーバーにはハッシュで保存。
- 確認ページには「このコードは誰にも教えないでください。心当たりがなければ閉じてください」と受付日時を表示する。
- リンクを押しただけではログインしない(コードを入力した端末だけがログインする)。

### 自動ログイン
- 2回目以降は、端末に保存したログイン情報(長期間有効なセッショントークン)で自動ログインする。
- 再ログイン・他の端末からのログインは、ユーザー名を入力して上の流れで認証コードを入力する。
- 注意: iPhone の Safari は7日間開かなかったサイトの保存データを消すことがある(ホーム画面に追加していれば消えない)。
  その場合は再ログインが必要。

## 2. ユーザー名

- 見えない文字(空白・全角スペースを含む、制御文字・ゼロ幅文字など)は使えない。
- 大文字小文字・全角半角は **別の名前** として扱う(一意の判定も区別する)。
- 禁止: **「ゲストユーザー」で始まる名前だけ**(「CPU」「ＣＰＵ」などは許可)。
- 登録後の名前変更は可能。**一度変えたら30日間は変更不可**。
- 変更前の名前・削除したアカウントの名前は **5分経てば** 他の人が使える。

## 3. ゲスト(ログインなし)

- 名前は「ゲストユーザーn」。番号は **日本時間の日付ごと・端末ごとに固定**(同じ端末・同じ日なら同じ番号、日付が変わると振り直し)。
  1日の中で番号が重ならないよう、サーバーが Firestore の「その日の番号表」から配る(サーバーが再起動しても重ならない)。
- ゲストは名前を変えられない。
- 使える: 交流戦・ルームへの参加・観戦・CPU対戦(牌譜は記録しない)。
- 使えない: ルーム作成・段位戦・フレンド・戦績・牌譜。

## 4. 段位戦・交流戦

- 自動マッチングを「段位戦」と「交流戦」に分ける(それぞれ一荘戦/半荘戦を選ぶ。同じ種類・同じルールの人とだけ組む)。
- 段位戦はログインした人だけ。持ち時間は今と同じ(5+20秒)。
- 段位戦は再戦なし(最終結果画面は「ロビーに戻る」だけ)。
- 段位は一荘戦・半荘戦で **共通**(1つの段位・ポイント)。

### 段位表

- 登録直後は 10級・0pt。
- **昇段**: 昇段ラインに届いたら次の段位の初期ポイントから(超えた分は切り捨て)。十段が昇段ラインに届いたら **師範代**。
- **降段**: 初段〜十段のみ。0pt を割ったら1つ下の段位の初期ポイントへ(初段は 1級・0pt へ)。
- **師範代**: ポイントなし・昇段降段なし(対局しても変わらない)。

### ポイントの計算(1局ごと)
勝敗は最終の持ち点で決める(多い方が勝ち、同点は引き分け)。

1. **引き分け**: どの段位でも増減 0。
2. **通常**(相手との段位差が 2 以下):
   - 勝敗分 = 上の表の勝ち/負けの値。**一荘戦は勝敗分だけ 1.5倍**(5の端数はそのまま。例: -30 → -45)。
   - 点差分 = (最終の持ち点 − 45,000)÷ 2,000 を **0 に近い方へ切り捨て**(例: 58,500点 → +6、31,000点 → -7)。
   - 増減 = 勝敗分 + 点差分。
3. **段位差が3以上**、または **相手が師範代**:
   - 勝敗分 = 勝ち +5 / 負け -10(一荘戦でも 1.5倍しない)。
   - 点差分 = (最終の持ち点 − 45,000)÷ 10,000 を 0 に近い方へ切り捨て。
   - 増減 = 勝敗分 + 点差分。
   - 段位差は20段階(10級〜十段)の中での位置の差で数える(例: 1級と三段は3)。
4. **10級〜3級**は、合計が負になる場合は 0(減点なし)。
5. 師範代自身は増減なし。

### 途中退室・切断
- 段位戦の途中で退室した人、または切断して5分以内に戻らなかった人は **負け**。
  **今の段位の負け(勝敗分)の2倍** を失う(点差分なし)。例: 十段 半荘 -240 / 一荘 -360(-120×1.5×2)。
  10級〜3級は 0。段位差3以上・師範代相手のときの扱いも同様に「そのときの負けの勝敗分 × 2」(10級〜3級は 0)。
- 残された側: 勝敗分なし。その時点の持ち点が 45,000点を上回っていれば 2,000点ごとに +1pt(切り捨て)、下回っていれば 0。
- 両者とも切断して戻らなかった場合: 両者とも増減なし。

## 5. フレンド

- 申請方法:
  - 交流戦・ルーム対戦の最終結果画面の「フレンド申請」ボタン(2人とも登録済みのときだけ表示)。
  - ユーザー名で検索して申請。
- 2人とも申請したらその時点でフレンド。片方だけの申請は残り、後から相手が承認/拒否できる。
- フレンド一覧: 受け取った申請の承認・拒否、フレンドの解除。
- フレンド数の上限: 30人(後で変更するかもしれないので設定値にする)。
- できること: 一覧、オンライン表示(対局中かどうか)、ルームへの招待、戦績・段位の閲覧、フレンドの対局の観戦。
- 観戦の許可(ルーム作成時): 「許可する / フレンドのみ / 許可しない」。「許可しない」はフレンドでも観戦不可。
  3分遅れ・進行中の局の手牌の伏せはフレンドにも同じくかける。

## 6. アカウントの削除・メールアドレスの変更

- 削除: ログイン中のみ・認証コードで本人確認。段位・戦績・フレンドのデータを消す。名前は5分後に再利用可能。
- メールアドレスの変更:
  1. ログイン中に「引継ぎコード」を発行(推測できない長い文字列・1回限り・有効期限付き・サーバーにはハッシュで保存)。
  2. 引継ぎコードと新しいメールアドレスを入力。
  3. 新しいアドレスに届いたメールで認証コードを受け取り、入力すると変更完了。

## 7. 進め方

1. アカウント(登録・ログイン・自動ログイン・ゲスト名・名前変更・削除・メールアドレス変更・プライバシーポリシー)
2. 段位戦・交流戦(自動マッチングの分割・段位とポイント・戦績)
3. フレンド(申請・一覧・オンライン表示・招待・戦績の閲覧・観戦・「フレンドのみ」の観戦許可)
